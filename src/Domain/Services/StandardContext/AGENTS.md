# Domain/Services/StandardContext — 标准方法号解析

> 本文件是该目录的**协作入口文档**。接手前请先读完本文档，即可掌握：
> 本目录解决什么问题、类职责、方法契约、解析规则的已知局限。
>
> 最后更新：基于 `ffa16de`，模板索引按「测试方法」匹配的改造引入。

---

## 1. 一句话定位

**把具体标准号（`ISO 12945-2:2020` / `BS EN ISO 12945-2:2010` / `GB/T 12945.2-2017`）归纳为「方法级键」（`ISO 12945-2`），供模板索引按测试方法匹配。**

### 为什么需要它

模板索引（`TemplateIndex`）是精确字符串匹配：`ISO 12945-2` 与 `BS EN ISO 12945-2` 是两个不同的键。若不归一化，同一个 Martindale 起球模板要为每个变体各配一条索引，漏配就匹配不到。

### 为什么不用标准族（StandardFamily）

族的粒度是 `ISO 12945`，**会把方法一（`12945-1`，ICI 起球）与方法二（`12945-2`，Martindale 起球）合并**，反而破坏模板索引的唯一性。本目录的解析器**保留方法号**，粒度落在「方法」这一级 —— 这正是它与 `StandardFamilyCode` 的本质区别。

## 3. 方法契约

### `string? Resolve(string? standardCode)`

| 项 | 内容 |
|---|---|
| 入参 | 数据库中的标准号原文；允许 null / 空白 / 非标准号文本 |
| 返回 | 方法级键；无法识别出任何数字编号时返回 `null` |
| 异常 | **不抛异常**（脏数据不应阻断整条生成链路） |
| 副作用 | 无。纯函数，无外部依赖，可安全并发调用 |

**为什么不抛异常**：解析失败的正确处置由调用方决定。当前调用方（`TestConditionComposer`）的策略是「解析不出就不注入该条件键」，让模板匹配退化为只用 `TestMethod`，而不是让一次生成整体失败。若将来要求「解析失败必须阻断」，改调用方即可，解析器无需变动。

## 4. 解析规则（启发式，非完备）

处理顺序**不可调换**，每一步的原因见代码注释：

| 步骤 | 处理 | 例 |
|---|---|---|
| 1 | 去尾部版本年份（`[:\-]\s*\d{4}$`） | `ISO 12945-2:2020` → `ISO 12945-2` |
| 2 | 归一方法号写法 | `12945.2` → `12945-2`；`Part 2` → `-2` |
| 3 | **循环**剥离采纳前缀（BS / EN / DIN / NF / SIS / SS / SANS / UNI / NEN / SN / AS / JIS） | `BS EN ISO 12945-2` → `EN ISO 12945-2` → `ISO 12945-2` |
| 4 | 压缩空白、校正 `-` 两侧空格 | `GB/T  12945 - 2` → `GB/T 12945-2` |
| 5 | 无数字 → 返回 null | `MARTINDALE` → `null` |

### 已验证的用例

| 输入 | 输出 |
|---|---|
| `ISO 12945-2` | `ISO 12945-2` |
| `ISO 12945-2:2020` | `ISO 12945-2` |
| `EN ISO 12945-2` | `ISO 12945-2` |
| `BS EN ISO 12945-2:2010` | `ISO 12945-2` |
| `ISO 12945-1` | `ISO 12945-1` |
| `GB/T 12945.2-2017` | `GB/T 12945-2` |
| `AATCC 124` | `AATCC 124` |
| `ISO 6330` | `ISO 6330` |
| `Martindale` / `""` / null | `null` |

### 已知局限（不要当成 bug 修）

1. **跨体系等价无法识别**：`AATCC 124` 与 `ISO 7768` 功能等价但编号体系不同，解析器会给出两个不同键。这类等价关系属业务判断，只能靠人工映射（见未来方向）。
2. **`GB/T 12945.2` 与 `ISO 12945-2` 不自动归并**：前者保留了 `GB/T` 机构前缀。是否视为同一方法属业务决策，当前采取保守策略（不擅自归并）。
3. **前缀白名单是封闭集合**：出现未列入的国家/区域前缀（如 `KS`、`IS`、`NBR`）时不会被剥离，会得到带前缀的键。新增前缀请改 `AdoptionPrefixes` 并补用例。
4. **只处理编号型标准**：以文字命名的内部方法（如 "Martindale"）无法解析，返回 null。

## 7. 未来优化方向

1. **人工覆盖字段**：若某些标准号的启发式解析持续出错，在 `Standard` 上加可选的 `MethodCode` 覆盖字段（解析器优先取覆盖值，为空才走规则）。这也是把「业务知识」从代码搬到数据的路径。
2. **等价映射表**：跨体系等价（`AATCC 124` ↔ `ISO 7768`）需要一张人工维护的方法映射表。等真实需求出现再做，不要提前建。
3. **规则可配置化**：`AdoptionPrefixes` 目前硬编码。若前端需要运营自助维护，可改为配置项。
4. **补单元测试**：本目录是纯函数，最适合做表驱动测试（上面「已验证的用例」表可直接转为 `[Theory]/[InlineData]`）。当前工作区无测试项目。
